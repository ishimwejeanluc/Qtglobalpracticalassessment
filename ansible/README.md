# Tasks 2 and 3: VM configuration with Ansible

Ansible runs from the **laptop** (the control node) over SSH. It configures:
- **the Docker host:** Docker Engine and Compose (Task 2);
- **the 3-node Kubernetes cluster:** kubeadm, containerd and Calico (Task 3);
- **the app prerequisites on the cluster:** storage, namespace and Secret (Task 4).

No step is done by hand on a node.

## Layout

```
ansible/
├── ansible.cfg                     inventory path, SSH pipelining, YAML output
├── requirements.yml                collections: community.general, ansible.posix
├── inventory/
│   ├── hosts.ini                   GENERATED by Terraform (iac/inventory.tf): groups docker, control_plane, workers, k8s
│   └── group_vars/
│       ├── all/main.yml            app settings and secrets, read from docker/.env (one source of truth)
│       └── k8s.yml                 Kubernetes version, CIDRs, Calico / metrics-server / Gateway API versions
├── playbooks/
│   ├── site.yml                    docker-host.yml + k8s-cluster.yml
│   ├── docker-host.yml             Task 2: prepare c3-docker-host
│   ├── k8s-cluster.yml             Task 3: build the cluster
│   └── k8s-app-prereqs.yml         Task 4: storage dir, namespace, Secret
└── roles/  (see below)
```

## Roles

| Role | Hosts | What it does |
|---|---|---|
| `common` | all | apt cache, base packages (incl. `sysstat` for `iostat`), grows the root LV to the whole disk |
| `docker_repo` | (dependency) | Docker's apt repository and GPG key. Shared by `docker_engine` and `containerd` |
| `docker_engine` | docker | Docker Engine, the Compose plugin, `daemon.json` (log rotation), the `devops` user in group `docker` |
| `containerd` | k8s | containerd from Docker's repo. Generates the default config with **`SystemdCgroup = true`** and the CRI plugin enabled. Enabled at boot |
| `k8s_node` | k8s | Swap off (now and in fstab), kernel modules `overlay` and `br_netfilter`, sysctl (`ip_forward`, bridge-nf-call). pkgs.k8s.io repo for **v1.35**; `kubeadm`, `kubelet` and `kubectl` installed and **held** (`apt-mark hold`), so they can't be upgraded by accident |
| `k8s_control_plane` | control_plane | `kubeadm init` from a template (pod CIDR `10.244.0.0/16`), **only if `/etc/kubernetes/admin.conf` doesn't exist**. Sets up kubectl for `devops`, saves the kubeconfig to `ansible/kubeconfig` (git-ignored) |
| `k8s_worker` | workers | Creates a **fresh, short-lived join command** on the master (`kubeadm token create --print-join-command`) and runs it, **only if the node hasn't joined** (`/etc/kubernetes/kubelet.conf` missing). The token is never stored or logged |
| `k8s_addons` | control_plane | Calico (Tigera operator), metrics-server, Gateway API CRDs and Envoy Gateway. Each manifest is diffed with `kubectl diff` and applied only when it differs. Waits until all nodes are Ready |
| `k8s_app_prereqs` | control_plane | MongoDB data directory on worker-1 (uid 999, mode 2770). Namespace `qt-spring-app` (Pod Security restricted plus default-deny). Secret `projecthub-secrets` from `docker/.env`, sent through stdin with `no_log` |

**Why Calico?** It enforces **NetworkPolicy**, which Flannel does not, and the app uses NetworkPolicies to isolate MongoDB and Valkey. The pod CIDR `10.244.0.0/16` doesn't overlap the LAN `192.168.160.0/24`.

## Run

```bash
cd ansible
ansible-galaxy collection install -r requirements.yml
ansible all -m ping                                  # SSH to all 4 VMs

ansible-playbook playbooks/docker-host.yml --syntax-check
ansible-playbook playbooks/docker-host.yml          # Task 2 host
ansible-playbook playbooks/k8s-cluster.yml          # Task 3 cluster  (or: playbooks/site.yml for both)
ansible-playbook playbooks/k8s-app-prereqs.yml      # before the first Helm deploy
```

## Idempotent and safe

- **Running any playbook a second time reports `changed=0`.**
- **No destructive steps:**
  - `kubeadm init` and `kubeadm join` are guarded by file checks;
  - there is no `kubeadm reset` anywhere;
  - add-ons are diffed before they are applied.
- **Secrets:** no secret is written in the playbooks. They come from `docker/.env` (git-ignored) through `ini` lookups, are sent to `kubectl` through stdin, and their tasks use `no_log`.
- **Privileges:** `become: true` only where root is needed. `kubectl` tasks run as the cluster admin on the master.

## Verify the cluster

```bash
export KUBECONFIG=$PWD/kubeconfig        # from the ansible/ folder
kubectl get nodes -o wide                # 3 nodes Ready, v1.35.x, containerd://2.x
kubectl get pods -A                      # calico-system, kube-system, envoy-gateway-system all Running
kubectl cluster-info
kubectl get --raw='/readyz?verbose' | tail -3   # replaces the deprecated "kubectl get componentstatuses"
kubectl top nodes                        # metrics-server works
ansible k8s -b -a 'systemctl is-active containerd kubelet'
```

Pod-to-pod networking across nodes is proven by the app itself: the API pods on worker-2 reach MongoDB on worker-1 (`/api/health` → `"database":"up"`).
